# Notified – Associate Web Developer Technical Assessment

**Prepared by:** Robert Quintero
**Position:** Associate Web Developer

## 1. Project Overview

The objective of this assessment was to recreate the provided corporate investor relations website mockup using HTML and CSS, with a focus on visual accuracy and responsive design.

Although the assessment required only one implementation, I decided to develop two separate versions using Drupal and Next.js. This allowed me to demonstrate my familiarity with the CMS technology mentioned in the job description while also showcasing my current frontend development workflow.

Both implementations are based on the provided desktop mockup and include responsive layouts for smaller screen sizes.

## 2. Why I Developed Two Implementations

Since the assessment provided a one-week completion period, I decided to use the opportunity to explore two different approaches to implementing the same design.

### A. Drupal Implementation

The job description specifically mentions Drupal 10 and Twig. Since I have experience working with CMS-based development, I wanted to demonstrate how I could translate the provided design into a Drupal environment.

This implementation also allowed me to explore the integration of the design within a content management system rather than limiting the assessment to a standalone frontend application.

### B. Next.js Implementation

I also developed a separate version using Next.js because it is the framework I currently use for my personal and freelance development projects.

This implementation reflects my current development workflow and approach to building responsive frontend applications.

I used Tailwind CSS for styling and relied primarily on native Next.js functionality. I intentionally avoided additional UI component libraries and unnecessary third-party dependencies to keep the project lightweight and easier to maintain, particularly when updating the framework or modifying the application.

## 3. Design Process and Observations

### Initial Design Review

I started by reviewing the supplied desktop mockup and identifying its main sections, layout structure, typography, colors, spacing, and visual elements.

During the review, I noticed some inconsistencies in the reference design, particularly in padding, spacing, typography, text alignment, and color usage across certain sections.

For the Next.js implementation, I prioritized reproducing the supplied reference as closely as possible, keeping the original appearance and layout consistent with the provided mockup.

For the Drupal implementation, I took the opportunity to address some of the observed inconsistencies and make minor visual refinements while preserving the overall design direction.

### Mobile Design in Figma

Since the assessment only provided a desktop mockup, I created an additional mobile design in Figma before proceeding with the responsive implementation.

This gave me a visual reference for how the different sections should adapt to smaller screens, including changes to spacing, content arrangement, and layout behavior.

I then used these designs as references when implementing the responsive layouts in both versions.

## 4. Technical Implementation

### Next.js and Tailwind CSS

For the Next.js version, I used:

- Next.js for the application structure and frontend development.
- Tailwind CSS for styling and responsive layouts.
- Native Next.js functionality wherever applicable.

I avoided additional UI component libraries to minimize external dependencies and keep the codebase straightforward to maintain.

### Drupal and CSS

For the Drupal version, I implemented the design within a Drupal environment.

I initially used Tailwind CSS for styling. However, I encountered some limitations in the existing setup where certain Tailwind utilities did not behave as expected.

To address this, I supplemented the implementation with standard CSS for specific elements and layouts where necessary.

This allowed me to achieve the intended appearance without relying entirely on utilities that were not working correctly in that environment.

## 5. Responsive Design and Testing

Both implementations include responsive adjustments to accommodate different screen sizes.

The mobile layouts were based on the additional Figma designs I created, rather than simply scaling down the desktop layout.

During implementation, I focused on:

- Adjusting section layouts for smaller screens.
- Maintaining appropriate spacing and padding.
- Ensuring text remains readable.
- Adapting content arrangement to available screen widths.
- Maintaining visual consistency across desktop and mobile layouts.
